# 空间变换与SteamVR坐标系

把一个VR窗口想成一张有刻度的纸。应用知道纸上哪里有按钮，SteamVR知道这张纸在房间里的位置，手柄给出一束有起点和方向的光。所谓空间UI，首先就是让这三件事说同一种几何语言。把纸转个角度、让它跟着手柄移动，或者把纸弯成弧面，按钮的位置仍然由纸上的刻度定义。

本章沿着一个连续问题展开。先把像素送到空间，接着逆向求出激光落在哪个像素，最后用同样的坐标变换解释窗口移动、旋转、缩放和曲率调节。阅读时可以把纸、笔和桌沿当作坐标轴。下文用`X/Y/Z`表示空间三轴，用`left/top`表示窗口上的逻辑像素，用`R`表示旋转或在柱面小节单独表示半径，用`T`表示同时包含旋转和平移的位姿。

## 1.先把坐标系立起来

### 原点规定从哪里量，坐标轴规定怎样量

把纸的左上角按在桌面一个点上，规定向右数格为正，向下数格也为正。纸上的`(120,80)`是两次有方向的位移。换一张纸，纸上的`(120,80)`可以描述同一个版式，却落在桌面另一个地方。纸的左上角可以换地方，纸的方向也可以转动，这就是三维变换中的平移和旋转。

三维坐标系比纸多一个轴。取两条垂直的单位轴以后，第三条轴还可以有两个相反的指向。右手系规定`eX × eY = eZ`。右手食指指`+X`，中指指`+Y`，拇指给出`+Z`的方向。左手系若保持同样的前两根轴，则第三根轴反向。手性是三根轴的相对约定。物体在空间里转动只会一起转动它的三根轴，原本为右手系的轴组转完仍是右手系。单独翻一根轴才改变手性。看镜子时左右像互换，就是为什么不能把镜像当成一个普通旋转直接塞进四元数。

SteamVR跟踪以右手系表示。头显姿态为单位旋转时，`+X`朝右、`+Y`朝上。由右手定则，`+Z`指向佩戴者一侧，视线前方因此用`−Z`表示。这是设备局部轴在零旋转时与跟踪空间的对齐约定。转头后，前方是头显旋转作用于`(0,0,−1)`的结果。举例，按右手定则绕`+Y`旋转`90°`，原来沿`−Z`的视线转到`−X`。用这组简单方向做一次实验，比记住“偏航角为正就朝哪边”可靠，因为用户也可能用不同的语言称呼左右转头。

另一种经常混淆的量是位置和方向。位置`(0,1.6,−1)`说明一个点离原点有多远。方向`(0,0,−1)`说明往哪边走。把整个坐标系平移一米，点的位置坐标会受到平移影响，方向的三个分量只有坐标轴转动时才需要重算。激光的起点属于前者，方向属于后者。求交代码分别变换这两项。

### 逻辑像素与米的换算

设窗口逻辑宽高为`w、h`，像素缩放倍数为`s = physical_scale`。定义下面三个量，后面所有公式都重复使用它们。

```text
m = s / LOGICAL_PIXELS_PER_METER = s / 1000
W = w · m
H = h · m
```

`m`的单位是米每逻辑像素，`W`和`H`是物理宽高。SDK在`render_style.h`定义`LOGICAL_PIXELS_PER_METER`，`window::get_physical_width()`和`window::get_physical_height()`按这套公式计算。Engine的`service_runtime::get_physical_width()`同样以`1000`为基准。输入辅助表面有一个例外，Engine在有当前拥有窗口时使用拥有窗口的`physical_scale`。

当`s = 1`时，一个逻辑像素对应一毫米。`640×360`窗口的物理大小是`0.64×0.36`米。在同一窗口上把`s`从`1`调到`1.5`，物理大小变成`0.96×0.54`米。这个操作改变窗面在VR中的大小，控件矩形仍然用原来的逻辑像素。把分辨率从`640×360`改成`960×540`而仍用`s = 1`，物理大小也会是`0.96×0.54`米，绘制目标和控件布局坐标却变了。两种结果的空间尺寸可以一样，交互与资源开销会不同。若要改逻辑分辨率又保留物理宽度，应按新旧逻辑宽度之比反向调整`s`。

以左上角为原点时，平面上一点的局部空间坐标为`(m·left, −m·top, 0)`。负号来自纸上的`top`向下增大和VR的`+Y`向上的区别。以窗面中心为原点时，先让像素坐标相对中心，再换算为米。

```text
左上角原点 A 中的点  pA = (m·left, −m·top, 0)
从左上角到中心       cA = (W/2, −H/2, 0)
中心原点 C 中的点    pC = (m·(left − w/2), m·(h/2 − top), 0)
两种写法的关系       pA = cA + pC
```

这里的`w/2`表示两个边界中点，宽`640`时是`320`。窗面命中使用连续坐标，`left`可以为`120.25`。像素位置用于布局与命中，绘图采样落在哪个离散纹理像素由渲染处理。若一上来就把落点取整，有些线条和命中边缘会在接近阈值时抖动。

`window.position`及协议中的`metadata.position`描述参考系下的左上角位姿平移部分。Engine的`resolve_pose()`与SDK的`get_anchor()`还原这个左上角位姿。Engine的`get_center_pose()`与SDK的`get_world_pose()`再组合中心偏移。公开的`window::get_world_transform()`调用`get_world_pose()`，得到的是世界空间的中心位姿。拿`position`和`get_world_transform()`的平移部分直接对比时，先确认两者的参考系与原点是否一致。

例如在单位参考系、零旋转下，左上角`A = (0,1.6,−1)`，宽高与上例相同。中心是`C = (0.32,1.42,−1)`，`(left,top) = (120,80)`相对中心是`(−0.20,0.10,0)`，相加得到世界坐标`(0.12,1.52,−1)`。若把`A`错当成`C`，结果会整体偏移半宽和半高。若只忘了`top`的负号，竖直方向会镜像。同一模型可以分别诊断这两种错误。

## 2.用向量做投影、判断朝向和构造坐标轴

### 点乘把一个方向的分量取出来

向量可以读成有方向的箭头。`a = (3,4,0)`可以表示从起点向右走三步、向上走四步。长度是`sqrt(3² + 4²) = 5`。`vec3_t::get_length()`用三参数`hypot(x,y,z)`计算。坐标相减给出两点间的位移，坐标相加可用于“起点加位移”。对方向向量乘以负数会反向，乘以正数只改长度。

点乘`a·b = ax·bx + ay·by + az·bz`，也等于`|a|·|b|·cos(φ)`，其中`φ`是两个非零向量的夹角。把`b`归一化为单位向量`b̂`以后，`a·b̂`就成了`a`沿这条轴的有符号长度。若`a = (3,4,0)`、`b̂ = (1,0,0)`，投影长度是`3`，对应投影向量`(3,0,0)`。若基轴改成`(−1,0,0)`，长度变成`−3`，投影向量仍是`(3,0,0)`。符号用于描述相对于指定正方向的朝向。

直角坐标里，已知点和三根正交单位轴，用同一个位移分别点乘每根轴就得到三个局部分量。对于平面法线`n`与射线方向`d`，`d·n = 0`意味着射线平行于切平面，趋近零意味着非常斜地入射。`d·n < 0`表示射线朝向正面法线的反方向，从法线指向的一侧打向表面。`d·n > 0`则是背面入射。SDK用`vec3_t::calculate_dot_product()`计算这些量。在后面讨论曲面时，法线会随横向位置改变，因此正背面要看命中点处的法线。

要从两个单位向量算实际角度，可以用`acos(clamp(a·b,−1,1))`。限制区间是为了防止舍入把理论上的`1`变成稍大于`1`的数。若只需要比较“哪个更朝前”，直接比较点乘既省计算也避免把一次比较变成角度反三角运算。要表达带符号的转角，还需要约定轴方向，用后面相位公式中的`atan2`区分绕轴的正负方向。

### 叉乘给出垂直轴，顺序决定正负

叉乘输出的是向量。表达式如下。

```text
a × b = (ay·bz − az·by, az·bx − ax·bz, ax·by − ay·bx)
|a × b| = |a|·|b|·sin(φ)
```

拿`a = (1,0,0)`和`b = (0,1,0)`代入，得到`(0,0,1)`。将二者换位得到`(0,0,−1)`。SDK的`vec3_t::calculate_cross_product()`使用相同的分量式。叉乘同时给出平行四边形的面积和垂直方向。两条输入箭头几乎平行时，面积趋近于零，垂直结果很短。此时放大成单位向量，会同时放大测量噪声。

一个常见构造是已知所需的前方单位向量`f`和大致“上方”`u`，要求产生右手的右、上、朝后轴。因为局部`−Z`朝前，先取`z = −f`，再令`x = normalize(u × z)`，然后令`y = z × x`。使用时先检查`u`和`z`是否近乎平行。若需要稳定构造，遇到退化就从其他参考轴选一根方向差更大的轴，或者暂时保留前一帧的方向。给定三根有效正交单位轴后，SDK的`quat_t::create_from_axis_basis(a,b,c)`把它们作为旋转矩阵的三列转换成四元数。源码先计算矩阵迹`a.x + b.y + c.z`，当迹为正时通过标量分量求其余分量，其他情况选最大的对角分量作为稳定入口，最后归一化。把行列想反会把一个从局部到世界的旋转错误地写成它的逆旋转。

严格来说，用世界坐标描述局部`X`轴的向量就是矩阵第一列。矩阵乘上`(1,0,0)`会选中这一列。乘上`(2,3,0)`则相当于沿第一列走两份、第二列走三份。这也是“旋转矩阵的列代表轴”最好用的检验方法。

### 归一化先稳住数值范围

通常把向量除以长度称为归一化。计算`(1e300,1e300,0)`的长度时，直接平方可能先溢出。非常小的值则可能在平方时下溢成零。SDK的`vec3_t::get_normalized()`先检查有限值，然后找到最大分量的绝对值`M`。以`M`缩放以后，各分量的绝对值都在`[0,1]`内，并且至少有一个绝对值为`1`。再在缩放后的范围里用`get_length()`得到长度，最后归一化。这个过程改变了计算路径，同时保留了数学结果，因为两次缩放都为正。

例如`(30,40,0)`先除以`40`得到`(0.75,1,0)`，长度`1.25`，再除得到`(0.6,0.8,0)`。对零向量和非有限分量，SDK报告`zero_direction`。四元数归一化也先以最大分量缩放，不过错误键为`invalid_rotation`。遇到“方向无法定义”，调用方要解决测量或输入条件，给它加一个随意的小数会引入方向跳变。

`numeric_limits<double>::epsilon()`描述靠近`1.0`时双精度的分辨率。从源码看，判定用途各不相同。`vec3_t::is_equal()`对分量比较使用`epsilon·max(1,|a|,|b|)`。SDK平面求交用`epsilon`检查方向的局部`z`，双手旋转中的最小有效投影长度则使用真实物理阈值`0.02`米。把这三类阈值混成一个常数，单位和实际含义都会丢失。数值精度阈值解决浮点边界，物理阈值解决设备噪声与手势稳定性。

## 3.位姿把两个坐标系连接起来

### 点先旋转再平移

设`T_WA`表示把坐标系`A`中的数值变成跟踪空间`W`中的数值。它包含旋转`R_WA`和位移`t_WA`。对于一个点，先把局部基轴换成世界基轴，再把结果平移到局部原点的世界位置。

```text
P_W = R_WA · P_A + t_WA
D_W = R_WA · D_A
```

`pose_t::transform_point()`实质上执行`position + rotation.rotate(v)`。方向变换只用`rotation.rotate()`。例如平移`(1,0,0)`后，局部原点`(0,0,0)`到了`(1,0,0)`。同一个轨迹的切线仍朝原先方向。若对方向调用变换点的函数，得到的射线会随窗口离全局原点的距离改变方向，表现为窗口挪到另一处后命中突然变歪。

在本文的记号里，`T_WA · T_AB`表示先从`B`到`A`，再从`A`到`W`。把两个表达式展开可得到组合平移与组合旋转。

```text
P_A = R_AB · P_B + t_AB
P_W = R_WA · (R_AB · P_B + t_AB) + t_WA
R_WB = R_WA · R_AB
t_WB = t_WA + R_WA · t_AB
```

这正是`pose_t::operator*()`的两项实现。小坐标系的位移属于大坐标系的局部方向，需要先旋转。想象左手握着一张纸，纸距手柄局部右方十厘米。转手之后，这十厘米仍然是手柄自身右方，在房间坐标里却会改变方向。直接将两个`position`逐项相加会让这十厘米固定在房间的正右方。

### 从世界回局部要使用完整逆位姿

从`P_W = R·P_A+t`解出`P_A = R⁻¹·(P_W−t)`。因此逆位姿的旋转是`R⁻¹`，平移是`−R⁻¹·t`。SDK的`pose_t::get_inverse()`先求四元数逆，再计算`q.rotate(position * −1.0)`。这里的平移和旋转须成对逆转。对一直沿坐标轴的图形，只减位置可能碰巧正确，转手或转头后才会显出问题。

可以手算一组完整链路。令参考系`A`的位置为`(1.00,1.50,−0.80)`，绕世界`+Z`转`90°`。窗口左上角在参考系的`(0.20,0.10,−0.50)`，相对参考系零旋转。窗口宽`600`、高`400`，`s = 1`。

1. 世界中参考系`+X`变成`+Y`，参考系`+Y`变成`−X`。所以把窗口的局部平移绕`Z`旋转后得到`(−0.10,0.20,−0.50)`，再加参考系原点。世界中的窗口左上角是`A_W = (0.90,1.70,−1.30)`。
2. 窗面中心相对左上角是局部`(0.30,−0.20,0)`。转成世界增量后为`(0.20,0.30,0)`，所以中心是`C_W = (1.10,2.00,−1.30)`。
3. 按钮中心的逻辑坐标`(150,100)`相对左上角是局部`(0.15,−0.10,0)`，相对窗面中心则是`(−0.15,0.10,0)`。用第一种写法，世界增量是`(0.10,0.15,0)`，按钮世界点为`(1.00,1.85,−1.30)`。用第二种写法，世界增量是`(−0.10,−0.15,0)`，加到中心后得到同一点。
4. 倒算时，从按钮世界点减去`C_W`得到`(−0.10,−0.15,0)`。逆转`90°`得到窗面中心系的`(−0.15,0.10,0)`。换回像素，`left = 300 − 150 = 150`，`top = 200 − 100 = 100`。若忘了逆旋转，就会把世界`(−0.10,−0.15)`直接当成窗口`x/y`，反算成`(200,350)`。命中的偏差会随旋转而变，正好可用来定位这类实现错误。

用框架表示每个窗口的前向链，窗口左上角位姿是`T_WA = T_WR · T_RA`。`R`在这里表示某个窗口参考系。若从中心系求平面点，再乘左上角到中心的固定偏移`T_AC`。逆向则是`P_C = T_AC⁻¹ · T_RA⁻¹ · T_WR⁻¹ · P_W`。世界点可以按这个式子依次转换，源码为了避免重复运算，直接合成中心位姿并求一次逆。最后从中心局部坐标换算像素。跟踪空间里有五种可选参考系，每个窗口只选其中一项作为该链的中间坐标系。

### 切换参考系、跟踪缺失与重置

`world`使用Engine的`world_origin`，其作用是让应用用易于摆放的局部坐标表示窗口。首次取得有限的头显位姿时，`initialize_world_origin()`把原点放在头显位置加站立轴`(0,0,−1.2)`处，初始方向为单位旋转。这里偏移沿跟踪空间的`−Z`，没有先乘头显旋转。`head`则使用实时头显位姿，局部`−Z`随头显一起转。`left`与`right`使用对应手柄的跟踪位姿，命中时Engine的`is_eligible()`限制为对侧手的激光。设备失去跟踪时，引用可为空。保留上一变换继续点击容易造成悬空的命中，所以这条路要先处理不可用位姿。

`body`建立在实时头显位置与固定参考朝向上。`BODY_HEAD_TO_NECK_OFFSET = (0,−0.075,0.08)`把头显原点指向一个名义上的颈部枢轴。将这个向量按当前头显姿态旋转并加到头显位置，得到估计颈部位置。随后用固定朝向把“颈部到头显”的反向偏移加回来，得到用于摆窗口的参考点。写成公式就是`p_body = p_head + R_head·d − R_body·d`，且参考系方向由`R_body`给出。转头时两项位置补偿减轻头显绕颈部运动带来的平移。补偿使用固定人体近似，调试时应把它与真实走动产生的位置变化区分开。`reset_body_center()`会记录重置时的完整头显旋转。

`Ctrl+Alt+Pause`的处理还可重置`world_origin`。设初次校准保存的`B = T_world_initial⁻¹ · T_head_initial`，重置前测得当前头显位姿`H`。让新参考系下测得的头显关系仍为`B`，解`T_world_new · B = H`，就得到`T_world_new = H · B⁻¹`。`reset_world_origin()`据此更新参考系。这里移动的是Overlay的参考系，应用窗口保留自身局部位姿关系。SteamVR站立空间与游戏角色的地图坐标由不同系统维护，用游戏摇杆移动角色不会自动改变这套物理跟踪位姿。

`reparent(reference, keep_world=true)`解的是另一条相似方程。先保存旧链算得的窗口世界左上角位姿`T_old`。选择新参考系`T_new_ref`后，要保持同一位置和方向，设置`T_new_local = T_new_ref⁻¹ · T_old`即可。SDK在`ui_runtime::reparent()`里通过`get_anchor()`、`get_reference()`和`change_transform()`实现。若`keep_world`为真且任一端的参考系失去跟踪，旧参考状态会保留，接口报告`reference_not_tracked`。若`keep_world`为假，窗口保留局部参数而切换参考系，也就是明确要把纸挂到新对象上。

默认居中属于首次摆放。没有有效来源窗口时，视线前方初始距离取`max(1.2,W,H)`米，先求中心，然后减去旋转后的中心偏移来写回左上角。若有有效来源窗口，初始中心和方向以来源窗口为准，并根据眼睛所在侧让新窗前移。已有近平行、范围重叠的窗口也参与深度间距检查。`STARTUP_DEPTH_OFFSET`为`0.02`米，接近眼睛时还会限制偏移量。拿静态数学例子推算实际的`center`位置时要记得这一步，尤其是多个窗口连续打开时。

## 4.欧拉角的顺序与万向节锁

### 三个角要配上一个明确的顺序

拿一支笔先平放成指向右方。绕桌面竖轴旋转一次以后，笔尖换了方向。再绕桌沿旋转时，结果取决于第一步把笔转到了哪里。两个旋转一般不可交换。取`eZ = (0,0,1)`，先绕`X`转`90°`得到`−eY`，再绕`Y`转`90°`仍是`−eY`。把顺序反过来，第一步得到`eX`，第二步仍是`eX`。用这个例子检查实现中“哪个乘法在前”，能避开语言中“依次相乘”带来的歧义。

SDK的`quat_t::create_from_euler(v)`以度为输入，`v.x/v.y/v.z`分别作为绕`X/Y/Z`的角。构造返回`qZ·qY·qX`。当向量从右边进入式子，先绕固定`X`、再绕固定`Y`、最后绕固定`Z`。这与用成组的局部中间轴解释同一个旋转矩阵可以等价，但两种说法的阅读顺序不同。为免把飞行术语误当公式，下文用`α/β/γ`直接表示`X/Y/Z`的角。无论把哪根轴称为俯仰、偏航或滚转，只有顺序与轴方向匹配，数字才有意义。协议的`metadata.rotation`按这组三轴度值传递，`tracking`和`pointer.rotation`传的是`[x,y,z,w]`四元数分量。

用列向量约定写出`R = Rz(γ)·Ry(β)·Rx(α)`。可对照最简单的绕`Y`矩阵，其第一列是`(cos β,0,−sin β)`，第三列是`(sin β,0,cos β)`。这说明转动后局部`X`轴和`Z`轴各指向哪里。继续乘上`Rz`并检查第一列，得到`(cos γ·cos β, sin γ·cos β, −sin β)`。中间角为`90°`时，第一列退化为`(0,0,−1)`，完全不再随`γ`改变。第三列和第二列还依赖`α`和`γ`，只是依赖二者的差。

### 两根控制轴在奇异姿态下代表同一个方向

在纸上画三个可转动的铁环，把第一个环套在第二个里，再套到第三个里。外环拨动时，里面两环一起被带走。直立时每次拨动可以改变不同方向。中间环转过直角以后，最里面的某根轴会和最外环的轴对齐。再去动这两个旋钮，实际是在同一根空间轴上叠加或抵消角度。

下式用矩阵给出准确情形。先把`Ry(90°)·Rx(α)`相乘，再乘`Rz(γ)`。令`δ = α−γ`，结果为

```text
R(α, 90°, γ) =
[  0      sin δ    cos δ ]
[  0      cos δ   −sin δ ]
[ −1        0        0   ]
```

只要差`δ`不变，两个角同时加任何相同值都得到相同姿态。`(0,90,0)`与`(90,90,90)`就是一例。还可以看瞬时转轴。从最终姿态看，改变最右边的`α`会绕`Rz·Ry·eX`产生增量，改变最左边的`γ`总是绕固定`eZ`产生增量。当`β = 90°`时，前者是`−eZ`，后者是`+eZ`。参数变化方向相反，空间直线却一样。三个控制旋钮的瞬时作用只剩两条独立方向，这就是自由度退化。`β = −90°`时对应另一种合并，姿态只依赖`α+γ`。

![欧拉角的轴重合与单位四元数的轴角表示](/images/zh/advanced_gimbal_lock_quaternion.png)

这件事解释了两个容易混淆的问题。第一，`(0,89,0)`与`(0,90,0)`当然只相差绕同一根`Y`轴的`1°`。第二，`(90,89,90)`与`(0,89,0)`虽在靠近奇异点时效果近似，二者在`89°`处仍有差异。代入第一列就能看出，前者的水平量在`Y`，后者的水平量在`X`。只是在靠近`90°`时，两者的水平量都很小，因为共同乘上`cos β`。这也是一个数值上易抖的区域。很小的测量误差可能要求欧拉角中的两个参数出现很大的变化，二者的变化又相互抵消，物体方向本身依然平稳。

万向节锁影响的是这组角在该点附近的独立控制与读数。刚体仍能向任意轴旋转。所谓“失去一个自由度”也有实际后果。例如动画系统用逐分量加法来控制镜头，在奇异姿态下，本来分别分配给`α`和`γ`的两个输入会变成同轴操作。若继续通过反算角度再做逐轴插值，还可能绕出不必要的大弧。三轴操纵界面在许多软件里可以按世界轴直接增量旋转，因此用户拖拽时不一定感觉到这个参数奇异。要判断内部表示，观察它怎样组合变化和怎样从姿态反求角度。

## 5.四元数从一根轴和一个角开始

### 轴角表示为什么用半角

以单位向量`û`为旋转轴，以`θ`为右手转角。数学书常把四元数写成`(w, v)`，标量在前，向量在后。本文以下用这个数学记号推导。SDK的实际聚合字段顺序是`quat_t{x,y,z,w}`，向量分量在前。构造绕`û`转`θ`的单位四元数时，SDK应存`{ux·sin(θ/2), uy·sin(θ/2), uz·sin(θ/2), cos(θ/2)}`。单位旋转是`{0,0,0,1}`。用标量在前的教材公式时，记得在代码初始化处换回实际字段顺序。

四元数乘法可以分成点乘与叉乘。设`a=(s,u)`、`b=(t,v)`，则

```text
a · b = (s·t − u·v, s·v + t·u + u×v)
```

左边的点代表四元数乘法，第一分量里的`u·v`是向量点乘。可以用`quat_t::operator*()`的第一和最后一项核验字段顺序。只要`u×v`有非零分量，交换两个操作数就会改变结果。这符合实际旋转不可交换的事实。把普通向量`p`放进纯四元数`(0,p)`以后，四元数乘法才能与向量旋转连接起来。一次只从左边相乘会产生标量分量，也改变了问题的含义。采用`q·(0,p)·q⁻¹`从两边作用，结果的标量重新为零。

令`q = (c, û·s)`，其中`c = cos a`、`s = sin a`。因为轴为单位向量，`c²+s²=1`，所以逆四元数是`(c,−û·s)`。利用上面的乘积式展开两次乘法，向量部分为

```text
(c²−s²)·p + 2cs·(û×p) + 2s²·û·(û·p)
```

再把`p`拆成平行轴的`p∥ = û·(û·p)`与垂直轴的`p⊥ = p−p∥`。轴向项的系数成为`c²−s²+2s² = 1`。垂直轴的两项是`(c²−s²)·p⊥ + 2cs·(û×p⊥)`。后面这两条向量等长又垂直，按三角公式`c²−s² = cos(2a)`、`2cs = sin(2a)`，正是让`p⊥`在平面上转`2a`。若希望向量转`θ`，四元数就需要用`a=θ/2`。这就是半角的来历。它来自两边相乘作用于方向的结果。

代入`û = eZ`、`θ = 90°`、`p = eX`。半角是`45°`，`c = s = √2/2`，轴向投影为零。式子第一项消去，第二项系数为`1`，剩下`eZ×eX = eY`。于是代码`quat_t::get_axis({0,0,1},90).rotate({1,0,0})`应该给出接近`(0,1,0)`的结果。`get_axis()`先检查角度有限、轴可归一化，再以`720°`对输入取余并乘`π/360`，这一步同时完成了度转弧度和折半。绕同轴转`360°`会得到`−q`所对应的同一空间旋转。表示值要绕`720°`才回到原来的四元数符号。

### 为什么可组合、为什么用共轭求逆

对任意四元数取共轭，是将向量部分变号。`q·q* = |q|²`是纯标量。严格的代数逆是`q*/|q|²`。SDK用于旋转，会先归一化再取共轭，确保实际返回的是单位旋转的逆。`quat_t::rotate()`也先归一化输入旋转，然后构造`{v.x,v.y,v.z,0}`，执行`(q·p)·q⁻¹`并取结果的`x/y/z`。四元数的字段可能由于浮点计算稍微偏离单位长度，因此这些归一化步骤有意义。

先用`a`转向量，再用`b`转，展开为`b·(a·p·a⁻¹)·b⁻¹`。按结合律重排得到`(b·a)·p·(b·a)⁻¹`。因此四元数乘积确实代表连续旋转，右边的项先作用。四元数的旋转组合保持单位范数，实践中仍会像源码那样定期归一化，控制误差积累。旋转的四个分量受单位长度约束，实际仍只有三个自由度。完整的四个值决定姿态，但`q`和`−q`表示同一姿态。单看某一个分量，它会同时受轴方向与半角影响，不能直接读成该轴欧拉角。

### SLERP与SDK当前插值实现

理论上的球面线性插值先将两个单位四元数视为四维单位球上的两点。若点乘为负，可把终点取反，让代表同一空间姿态的终点落到较短弧的一侧。之后设`Ω = acos(a·b)`。在`0<t<1`且`sin Ω`可稳定求值时，严格SLERP用下式。

```text
q(t) = sin((1−t)·Ω)/sin Ω · a + sin(t·Ω)/sin Ω · b
```

分母来自平面中两条端点向量的投影关系。可把终点写成`b = cos Ω·a + sin Ω·n`，其中`n`是与`a`正交的单位向量。沿弧走到比例`t`的点就是`cos(t·Ω)·a + sin(t·Ω)·n`。消去`n`便得到上式。两个角非常接近时，`sin Ω`很小，计算权重会放大误差，因此许多实现会在这个范围使用线性近似再归一化。

本项目的`quat_t::blend()`先做点乘判断和符号翻转，然后逐分量计算`a+(b−a)·t`，最后归一化。Python公开方法`quat.slerp()`绑定到这个行为。它是归一化线性插值，常写作NLERP。对于单位端点与区间`[0,1]`，方向沿相同的短弧变化，时间比例和球面弧长比例有差异。以固定轴从`0°`转到`120°`为例，严格SLERP在`t=0.25`给出`30°`。此时NLERP未归一化的标量和轴向分量分别是`0.875`与约`0.2165`，两者之比保持，反算转角约为`27.8°`。两端姿态一样，中间速度不同。若应用要求恒定角速度，采用严格SLERP公式，并保留近端点分支。SDK双手手柄旋转按相位变化直接构造轴角四元数，因此这条交互链不依赖插值速度。

## 6.从源码推导欧拉角与四元数互转

正向函数`create_from_euler()`只有一条乘法表达式，运算顺序已经规定。为了看懂逆函数，设`a = α/2`、`b = β/2`、`c = γ/2`，用`sx/cx`表示`sin a/cos a`，`sy/cy`与`sz/cz`依此类推。先写三个只有一根轴的四元数，再按`qZ·qY·qX`展开，得到

```text
x = sx·cy·cz − cx·sy·sz
y = cx·sy·cz + sx·cy·sz
z = cx·cy·sz − sx·sy·cz
w = cx·cy·cz + sx·sy·sz
```

逆解的关键是组合分量。把已展开的式子按`cy+sy`和`cy−sy`提取公因子，然后应用两角和差公式。

```text
(w+y, x−z) = (cy+sy) · (cos(a−c), sin(a−c))
(w−y, x+z) = (cy−sy) · (cos(a+c), sin(a+c))
```

`quat_t::get_euler_angle_vector()`第一步是`get_normalized()`。接下来计算上面两对的长度`difference = hypot(w+y,x−z)`和`sum = hypot(w−y,x+z)`。在规范分支`β∈[−90°,90°]`，`b`在`[−45°,45°]`。因此`cy+sy`与`cy−sy`都非负，长度就是这两个系数。再用和角式可写为

```text
difference = √2 · sin(b+π/4)
sum        = √2 · cos(b+π/4)
b+π/4      = atan2(difference,sum)
β          = 2·atan2(difference,sum) − π/2
```

这就是源码`ry`的计算式。对于其余两个角，源码计算`first = atan2(x−z,w+y)`和`second = atan2(x+z,w−y)`。前者还原`a−c`，后者还原`a+c`，所以`rx = first+second`、`rz = second−first`。代码用`remainder(角度,2π)`归到主值附近，再将弧度换成度。输入`β`若在规范分支以外，同一姿态可以用另一个三元组表达。逆解给出该分支上的表示。应用若往返比较，应比较旋转后的轴或姿态本身。

还要解释两条奇异点分支。当`β=90°`，`cy−sy=0`，第二对的长度`sum`为零，只有`first`有定义。代码令`second=first`，于是`rz=0`，把原来的`α−γ`合并进`rx`。当`β=−90°`，第一对的长度`difference`为零，代码令`first=second`，于是仍选`rz=0`，把`α+γ`合并进`rx`。实现用`epsilon`判断接近零的长度。它是在奇异姿态下选一个可重复的代表值。对一条连续轨迹，这个代表值可能在经过边界后跳到另一组角，因此渲染、跟踪与连续交互应先在旋转表示上计算，角度适合用作配置和显示。

验证公式可以做三组手算。单轴`(0,30°,0)`对应`q = {0,sin 15°,0,cos 15°}`。两对中的正弦分量均为零，故`rx=rz=0`，只逆出`30°`。第二组`(20°,90°,10°)`给出`rx≈10°、ry≈90°、rz=0°`。第三组取`(20°,−90°,10°)`，代表值为`(30°,−90°,0°)`。用两个姿态转同一组三个单位基轴可以验出它们等价。靠近奇异点时，与其比较显示的某个单独角，不如检查局部向前和向上的向量是不是同向。

## 7.柱面是怎样从平窗口弯出来的

### 保持弧长刻度与同一个中心切面

把平窗口中心放在`(0,0,0)`，未弯曲时表面在`z=0`。以物理宽度方向的弧长`u`和竖直米坐标`v`给它标刻度。令正曲率`κ`的单位是每米，半径`R=1/κ`。水平截面的圆心在`(0,R)`。把弧角定义为`φ = κ·u`，则中心局部点为

```text
u = (left / w − 1/2)·W
v = (h/2 − top)·(W/w)
x = R·sin φ
y = v
z = R·(1 − cos φ)
```

`u=0`时`x=z=0`，中心点及其切平面与平窗相同。随着左右两端`|u|`变大，`z`增加，窗口边缘向中心正面一侧弯。验证曲线方程，`x²+(z−R)²=R²`。弧长从圆周的角度换算出来，`u = R·φ`。整窗占用的角跨度是`Θ=κW`，左右边分别在`−Θ/2`与`+Θ/2`。若让`Θ`达到一整圈，两边就会重叠，同一空间位置将对应不同的横向逻辑刻度。`window::set_curvature()`、物理尺寸设置以及Engine的`present()`要求`κ≥0`且`κW<2π`。控制柄只允许不到`160°`的总角跨度，限制来自SDK的`get_maximum_handle_curvature()`，该函数用`nextafter`略向零取值。程序属性的合法域和交互控制柄上限各有用途。

`service_runtime::get_surface_local_point()`在`κ=0`时直接返回`(u,v,0)`。弯曲时将`z`写成`2·sin²(φ/2)/κ`。用恒等式`1−cos φ = 2·sin²(φ/2)`可看出二者等价。当角很小时，`cos φ`很接近`1`，直接做减法会丢掉很多有效位。半角式减少了这种消减。工程上也可以通过微分检查曲面刻度是否变形。固定`v`，沿`u`求导得到`(cos φ,0,sin φ)`，长度恒为`1`。所以横向像素之间依旧按弧长均匀分布。正面法线可写为`n=(-sin φ,0,cos φ)`，在中心回到`+Z`。几何上这是一条与水平切线、竖直方向都垂直的单位轴。

## 8.把激光世界点反算回窗口像素

### 先转射线，再解平面

射线由起点`o`和方向`d`定义，沿线点为`p(t)=o+t·d`。若`d`已归一化，`t`以米计。`t≥0`只取从起点朝激光发射方向的一侧。把中心位姿的逆作用到起点，只将逆位姿的旋转作用到方向。于是窗面中心系中的射线写成`o′+t·d′`。平窗上的`z=0`给出`o′z+t·d′z=0`，因此`t=−o′z/d′z`。若`d′z`为零，射线平行于平面。两项同时为零时，有无穷多个共面点。程序通常按没有可用的唯一命中处理，而由后续指针状态决定是否保留已捕获目标。

SDK的`ui_runtime::intersect_plane()`用于按下后的控件跟踪，使用`abs(ray.z) ≤ epsilon`判近似平行，拒绝`t<0`。返回的三值按`{t,local_x,local_y}`排列。这个返回值虽然借`vec3_t`携带，`x`字段的语义是距离参数，`y/z`字段才分别是平面横纵坐标。Engine的`service_runtime::intersect()`用于选择窗口，平面分支以`local_direction.z == 0`拒绝平行，候选筛选阶段还会拒绝`t≤0`和非有限值。两处函数都用相同的基础直线方程，但各自的容忍域和输出契约由调用目的决定。

例如中心系射线起点`(0.12,0.06,0.50)`、方向`(0,0,−1)`。求得`t=0.50`米，命中`(0.12,0.06,0)`。若宽高为`640×360`且`s=1`，回算`left=320+120=440`，`top=180−60=120`。检查`top`时，命中点的`y`为正说明它在中心上方，像素行号应比`180`小。这个直观校验比重做一遍坐标代数容易。

### 展开柱面方程与稳定求根

柱面可以从`x²+(z−R)²=R²`展开为`κ(x²+z²)−2z=0`，这里除掉了两边相同的`R²`并将等式乘`κ`。将射线的`x=ox+t·dx`、`z=oz+t·dz`带入，归并成`at²+bt+c=0`。

```text
a = κ·(dx²+dz²)
b = 2·[κ·(ox·dx+oz·dz)−dz]
c = κ·(ox²+oz²)−2oz
Δ = b²−4ac
```

这里省略了撇号，全部量都已在窗面中心系内。若方向仅沿柱轴`Y`，就没有唯一的横截面交点，`a=0`会被拒绝。`Δ<0`说明射线的横截面与圆不相交。`Δ=0`表示切线，与圆相切时只有一个重复根。`Δ>0`会得到两个候选，前后根还要筛选弧长与高度。

常见的直接求根式`(−b±sqrt Δ)/(2a)`有一项会在两个大值接近时相减，较小的根可能迅速失去精度。Engine先算`q=−0.5·(b+copysign(sqrt Δ,b))`，选同号相加避免消减。接着令两根为`q/a`和`c/q`。可由两根乘积`c/a`验证第二项。当`q=0`时改用`−b/(2a)`得到重根。代码还比较无量纲角跨度`κW`与`epsilon`，弯曲极小时按平面候选计算，再按实际曲率分量决定横坐标求逆式。这个做法可以避开在极小曲率下强行求一个很远的第二圆柱交点。

对于每个候选点，借助`κx=sin φ`及`1−κz=cos φ`反求弧角。`atan2`同时看两个分量，能区分左右半圆和同正弦值的另一支。令`u = atan2(κx,1−κz)/κ`，消费的逻辑像素是

```text
left = (u/W + 1/2)·w
top  = h/2 − (y/W)·w
```

通常要求`0≤left≤w`且`0≤top≤h`。这等价于把圆柱限制到窗口占据的角段和竖直高度。源码只保留正且有限的距离与有限像素，再取距离最小的有效根。不要在解出二次方程后只看最小根。较小根可能位于窗口的弧段之外，另一个才是用户看到的有限曲面。

### 一个可逐步验算的弧面例子

设宽度`W=1`米、`κ=1`每米、`w=1000`，并取`h=400`。窗口左右边界的弧角为`−0.5`和`+0.5`弧度。目标像素`left=750`、`top=200`对应`u=0.25`米、`v=0`，弧角为`0.25`弧度。将它代入正向模型，得到`x=sin(0.25)≈0.2474`、`z=1−cos(0.25)≈0.03109`。把一支激光放在`(sin 0.25,0,0.5)`处，令方向`(0,0,−1)`。求出该固定`x`处的两交点，`z`分别约为`0.03109`和`1.96891`。后者比射线起点还大，属于负`t`。前者得到`t≈0.46891`米。用`atan2`逆算得到原来的`0.25`弧度，再得到`750`与`200`。若粗略用`x=0.2474`米来换算，会误算成`747.4`左右，窗口弯曲越大，这种用弦位置代替弧长的误差越大。

同一个点的正面法线是`(−sin 0.25,0,cos 0.25)`，它与这里的`(0,0,−1)`点乘为负，说明是正面入射。Engine求交可以命中正面和背面。对于同一个曲面点，像素换算公式完全相同。背侧能看到反向的图像来自背侧Overlay的几何与纹理方向。SDK在开始空间捕获时在命中点使用法线与射线点乘，保存`capture.backside`。调曲率时可用它反转拖动的横向作用方向。选择正背面与选择最近的有效根是两件不同的事。

窗口处于捕获中时，Engine先求通常的有限面命中，再允许`outside`模式取得面外连续坐标。如果暂时没有新交点而目标仍有有效位姿，可沿用捕获状态。当没有捕获时，Engine在可见、可交互表面间找最近命中，并另外允许`BEAM_MARGIN_LOGICAL_PIXEL`定义的边缘范围作为激光显示候选。这样靠近边缘仍能看见光束，交互命中依然检查窗口边界。控件命中则发生在SDK，使用收到的`left/top`与控件几何进行选择。调试光标偏差时，依次检查空间射线是否到达窗面、算出的窗面像素是否正确，以及界面命中了哪个控件。

## 9.窗口交互如何使用这些几何量

### 单手移动保存的是相对位姿

按住握把键抓取窗口时，SDK用手柄原点和旋转组成手的位姿`H₀`，读取窗口世界左上角位姿`A₀`。`rebase_window_grab()`保存相对关系`G=H₀⁻¹·A₀`。随后手移动到`H₁`，`update_window_grab()`求得窗口新世界位姿`A₁=H₁·G`。要更新的窗口属性是在当前参考系`R`下描述的，最终写入`R⁻¹·A₁`。这三个乘法分别回答“抓住时纸在手的哪里”“现在那张纸在房间里的哪里”“把结果换回窗口自己的坐标系”。

保存整个相对位姿可以同时带动平移与旋转。试想用两指捏住纸的一个点并旋转手腕，纸的其他位置沿圆弧移动。距离较远时，同一个角度变化对应更大的横向位移。这是保持原始手柄到目标的相对关系所产生的几何结果。相对关系在捕获开始时建立，后续每次使用同一个`G`，因此不会把上一次舍入误差累计进下一次变换。

### 八个控制点如何限定双手旋转轴

窗体四周有八个控制点，按上、右上、右、右下、下、左下、左、左上的次序编号，其方向数组是`ROTATION_HANDLE_DIRECTION_LIST`。不同控制点必须由两手同时抓住同一窗口。抓相对的点时，`window::get_rotation_axis()`先归一化“第一个点指向第二个点”的窗口平面方向，再用`+Z×该方向`得到窗面内的旋转轴。因此抓上与下，轴落在`X`方向，抓左与右，轴落在`Y`方向，抓对角时轴为垂直于该对角线的面内斜轴。交换哪只手先占哪个点会改变轴符号。抓的两个点不相对时，源码返回`+Z`，用于绕窗面法线转动。通过选择点对，用户可以在有限的轴上精细调整。

每只手在抓取开始时保存命中距离。`update_window_rotation()`用`手柄原点+当前方向×捕获距离`计算两个虚拟抓点，再取差`span=P_right−P_left`。这个差先换到抓取起始时的窗面局部轴。对于`Z`轴旋转，取`span.x、span.y`做`atan2`。对于面内轴`a=(ax,ay,0)`，横向是`span·(ay,−ax,0)`，竖向是`−span.z`。两项就是向量在垂直于旋转轴的两根正交方向上的分量。`calculate_window_rotation_phase()`求出平面上的相位。投影长度小于`ROTATION_HANDLE_MINIMUM_SEPARATION=0.02`米时，相位读数不可靠，先暂停。重新取得有效相位时建立新的参考，不把失效期间的跳变一次性加进窗口。

相位在`π`处会换符号。比如上一帧是`179°`，下一帧记成`−179°`，实际增量应为`2°`。源码先对两帧相位差取`remainder(差,2π)`，再累计。然后从累计角与固定局部轴构造增量四元数，右乘到初始窗口旋转上。旋转中心在开始时保存，更新时重新计算左上角`A=center−R_new·(W/2,−H/2,0)`。所以窗面绕中心转，左上角随角度合理移动。若总是绕左上角转，玩家会感觉大窗口在手里甩来甩去。相位法需要有效的两点连线，但无需每帧猜测双手切到了曲面的哪一侧。

### 尺寸和曲率的控制柄用同一条捕获思路

右下角缩放柄与左下角曲率柄用扳机捕获。SDK留下初次命中的距离和位置，再将当前激光在同一距离上的点与初始点相减，得到窗口局部`(Δx,Δy,Δz)`。这样手柄拖动时追踪的是稳定的相对位移，避免因为每帧改变的曲面交点造成跳变。Engine收到带`lock_position`的`pointer_capture`请求，可以让光束的视觉端点跟随捕获点。拖动结束、目标失去交互资格或捕获取消时，SDK结束对应手势。

缩放要保持宽高比`r=h/w`。如果宽度改动`dW`，右下角的理想位移是`(dW,−r·dW)`。把实际局部位移投影到`(1,−r)`，最小化`(Δx−dW)²+(Δy+r·dW)²`，对`dW`求一次导数可得

```text
dW = (Δx − r·Δy) / (1 + r²)
```

这就是`update_pointer()`中的`width_delta`。例如`r=0.5`，拖动`(0.10,−0.05)`米，分子是`0.125`、分母是`1.25`，所以宽度增大`0.10`米。若只是水平拖出`0.10`米，同样公式得到`0.08`米，因为系统沿固定比例方向吸收了手势。`set_window_physical_width()`再用`s=1000·W/w`写回物理缩放，按交互最小宽度限制到至少`0.1`米，并在放大时必要情况下收紧曲率，保证弧角仍落于控制柄的范围内。

曲率柄使用横向局部位移，计算`κ_next=clamp(κ_initial ± 4·Δx,0,κ_max)`，正背面用相反的符号。`CURVATURE_DRAG_SENSITIVITY`为`4.0`。控制柄还接受摇杆。曲率读摇杆`X`，对总弧角做变化，满速每秒最多`2`弧度，因此对曲率的增量要除以当前物理宽度。尺寸读摇杆`Y`，用`W_next=W_current·2.25^a`，其中`a`由归一化摇杆速度与时间相乘。累加对数宽度等价于逐次乘比例，满速向上持续一秒在未触界时得到`2.25`倍，向下同样久则乘倒数。和每秒固定加零点几米相比，小窗与大窗的相对变化速度更接近。摇杆以`128`为中性点，代码先扣掉死区，再对两侧各自的有效范围做归一化。

双击展平的判断来自同一手的最近一次曲率柄释放。窗口ID相同且下一次按下与上次有效释放间隔未超过`CURVATURE_DOUBLE_CLICK_INTERVAL{500}`毫秒时，SDK置`curvature=0`，并要求先松开本次按键再开始下一次手势。它用同一条正常属性更新路径提交平面，后续Engine刷新Overlay时才反映显示状态。因此可分别记录SDK曲率变化与最终Overlay呈现，排查“已经展平但眼前仍显示旧弧面”的时序问题。

## 10.按层排错与练习

出现“窗口没显示”时，先问参考系当前有无有效跟踪，再问首次定位是否完成。若控件错位，先用单位旋转和`s=1`复现，然后只改变一项。只随尺寸产生的偏差通常和半宽或比例单位有关，只随头显转动产生的偏差通常和变换方向有关。只有曲面才出现的偏差，可以用左右对称点测试。对称点应得到相反的`x`、相同的`z`，命中则应回到对称的`left`。若从背面抓取时不稳定，记录抓取首次的法线符号和之后固定的捕获距离，区分翼端命中改变与实际旋转轴改变。

可用以下练习检查自己是否已经建立直觉。

1. 若`w=800`、`h=400`、`s=0.5`，窗面中心系里的`(left,top)=(200,300)`是多少？每像素半毫米，水平相对中心是`−200`像素，竖直向下`100`像素。答案为`(−0.10,−0.05,0)`。若对一条宽度变化做物理放大，不要同时把这个题目的`w`和`s`改掉。
2. 若`W=0.8`米而希望总弯曲角为`90°`，曲率是多少？先将角换成`π/2`，再除以`0.8`，得`κ≈1.9635`每米。此时OpenVR使用的圈数比例是`Θ/(2π)=0.25`，与`1.9635`这个物理曲率有不同单位。
3. 为什么一个方向为`(1,0,0)`的平面射线不能只靠其起点知道命中？因为代入`z`方程后`d_z=0`，沿射线的所有点拥有同一个`z`。起点在平面内则每一点都共面，起点不在平面内则无交点。求交函数需要的是可用于交互的唯一距离。
4. 为什么按钮点击处理拿到`left/top`后通常无需知道四元数？因为Engine已经把物理射线转换到窗面局部并恢复了逻辑像素。SDK只负责当时的控件几何、裁剪、焦点和事件链。几何层与界面层分别检查自己的契约，便可以单独验证。

逆向对照源码时，可从SDK的`geometry/vec3.cpp`、`geometry/quat.cpp`、`geometry/pose.cpp`开始，然后看`core/ui_runtime.cpp`中的参考变换，最后连到Engine的`core/service_runtime.cpp`与SDK的`core/ui_runtime_input.cpp`、`core/ui_runtime_grab.cpp`、`core/ui_runtime_scroll.cpp`。把每个分量标清是像素、米、度还是弧度，几乎每个式子的正负号与比例都能独立核对。
